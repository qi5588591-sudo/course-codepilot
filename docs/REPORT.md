# 面向开发者的智能代码生成与辅助工具课程设计报告

本文记录 CodePilot 的工程实现与当前验证结果。系统采用 VS Code 插件和 Python 后端，支持四种语言的智能辅助，并为 Python 提供测试反馈修复流程。本文为可编辑报告草稿，个人信息、个人体会和真实云端实验需在提交前补齐。

## 一、题目内容和要求

本项目选择课程题目 32“面向开发者的智能代码生成与辅助工具”。目标是减少重复编码工作，为开发者提供生成、补全、审查、测试、文档和错误修复能力，并集成到常用 IDE。

自然语言生成支持 Python、Java、JavaScript、C++。代码补全依据光标前后代码返回插入片段。审查输出问题行号、级别、原因和建议。测试生成覆盖正常、边界和异常输入。API 文档输出 Markdown。错误诊断支持用户粘贴日志和系统验证日志。IDE 集成采用 VS Code 侧栏、编辑器命令与原生行内补全。

首版自动执行限定于 Python，其他三种语言提供生成和辅助功能，编译与运行在对应工具链中进行。系统使用现成模型 API，未进行模型训练或微调。

## 二、问题背景和相关工作介绍

单纯展示大模型生成的文本，难以判断代码是否满足需求。开发者还需要将结果放回合适的位置、检查上下文兼容性，并通过测试确认边界行为。本项目将代码生成与编辑器交互、测试反馈和结果记录结合，形成可检查的开发流程。

VS Code 官方 Extension Samples 提供 Webview、命令和编辑器 API 的使用参考。Tabby 提供自托管代码助手的架构参考。Continue 提供代码助手交互的参考，其当前 README 声明仓库不再积极维护。本工程未直接复制这三个项目的源文件，具体记录见 THIRD_PARTY_NOTICES.md。

项目自主实现任务提示词、上下文整理、结构化结果解析、SQLite 历史、Docker 验证编排、固定测试修复和评估脚本。第三方框架负责 HTTP 服务、数据模型校验和编辑器基础接口，二者的工作量在报告中分别说明。

## 三、解题思路

系统分为插件、智能服务、记录存储和执行验证四部分。插件使用 TypeScript，后端使用 FastAPI，模型通过兼容 chat/completions 的接口接入。SQLite 保存每次任务的内容、模型名称、耗时、用量和验证轮次。

上下文由当前选区、光标前后片段以及用户主动添加的最多四个文件组成。Python 代码通过 AST 提取顶层导入、函数签名和类名，提供简明符号摘要。首版没有向量检索，也没有自动扫描整个工作区。

生成、补全、解释、审查、测试、文档、修复、命名和函数建议采用独立提示词。后端要求模型返回包含代码、解释、文档、问题和建议的 JSON 对象，并使用 Pydantic 校验。模型输出格式不合法时返回错误，不将任意文本当作可靠结构使用。

修改已有代码时，插件保存文档 URI、版本、原始文本和选区。预览使用虚拟文档展示差异。应用时再次核对文档版本和内容，避免旧建议覆盖新编辑。测试和文档默认打开为新文件，不替换原函数。

Python 验证先检查实现和测试的语法，再将其通过标准输入送入 Docker 容器。容器禁网、非 root、只读根文件系统，设置 256 MB 内存、单核 CPU、进程数及时间限制，不挂载宿主目录。缺少 Docker 或镜像时明确返回未验证。

自动修复保留固定测试，先验证当前代码，再将原需求、失败日志和测试交给模型。每次只更新实现代码，最多修复两轮。每轮保存实现、验证结果和测试 SHA256，便于追踪。测试通过仅说明满足当前断言，不证明不存在其他缺陷。

## 四、算法伪代码

上下文整理：读取选中代码和光标位置；截取限定长度的前后片段；合并用户添加的文件；若为 Python 则提取导入和函数签名；按照任务模板组织消息；请求模型并解析 JSON；保存结果并返回插件。

测试反馈修复：令 current 为原代码，tests 为固定测试；对 round 从 0 到 2 执行验证；记录代码、结果及测试哈希；若通过、环境不可用、无测试或超时则停止；若已达到最大轮数则停止；若测试本身语法错误则停止；否则以需求、current 和失败日志请求修复；将模型代码赋给 current，保留 tests，进入下一轮；返回全部记录和最后状态。

旧结果保护：生成请求时保存原文档标识、版本和原始内容；应用前重新打开文档；若任意一项不一致，则拒绝覆盖；否则以 WorkspaceEdit 替换原位置，由编辑器提供撤销能力。

## 五、实践设置

开发环境为 Windows，Python 3.12，Node 运行 TypeScript 编译器。依赖版本固定在 requirements.lock.txt 和 extension/pnpm-lock.yaml。执行镜像基于 python:3.12-slim，安装 pytest 8.3.5。后端默认仅监听 127.0.0.1:8765。

模型地址、名称、密钥由 .env 配置，密钥不进入插件和源代码提交包。补全默认采用手动触发，自动补全可在设置中打开。验证超时默认为 15 秒，自动修复最大两轮。

评估数据为本项目编写的 30 道 Python 生成任务和 15 道错误修复任务，每题提供需求、人工参考实现和独立断言。参考实现仅用于检查题目，不提供给生成模型。另有 Java、JavaScript、C++ 各三个参考示例，验证本机工具链和演示断言。

正式实验比较基础提示、加入上下文、加入测试反馈修复三种配置。统计首次通过率、最终通过率、平均耗时和 token 用量。首次生成不读取独立测试，修复阶段允许使用失败日志及固定测试。当前上下文评估只包含项目约定文件，跨文件语义能力尚需更丰富样本验证。

## 六、课程设计结果

当前实现已包含九类智能辅助任务入口、四语言参数、上下文文件选择、结果展示与保存、差异预览、版本保护、历史查询，以及 Python 验证和修复接口。插件已通过 TypeScript 编译并可打包为 VSIX。

本地 pytest 检查结果为 121 项通过、3 项跳过。检查覆盖 API 输入、模型响应解析、错误映射、任务历史、固定测试修复、执行限制以及评估题目。跳过项为需要真实 Docker 的集成测试。模型 HTTP 测试使用模拟响应，修复编排测试使用模拟执行器。

插件核心检查为 4 项通过，Webview 浏览器检查为 5 项通过。真实 VS Code 扩展宿主中的 6 个场景通过，覆盖生成上下文、差异预览、插入代码、旧结果保护、不可用验证状态和请求取消。宿主测试使用本地模拟模型服务，未测量云端模型效果。

Java、JavaScript、C++ 各三个参考示例均在本机工具链编译或执行成功，共 9 项。这些为手工编写的参考示例，不是模型生成结果。原始证据位于 artifacts 的 XML 与 JSON 文件。

当前机器未检测到 Docker，且没有提供项目模型 API 配置。因此真实容器执行、云端功能效果、45 题模型实验尚未实测，本文不填写模型准确率或提升百分比。配置完成后应运行 evaluation.run 并将真实 CSV 和典型失败案例补入本节。

## 七、结果分析

工程检查表明，系统可以对任务输入、生成结果、编辑位置和验证轮次进行明确管理。固定测试修复测试验证了实现代码更新与测试文本保留的逻辑；旧结果保护测试验证了文档修改后不会继续应用原结果。这些证据支持工程流程的正确性，但不能替代模型质量实验。

系统存在以下边界：自动执行目前仅支持 Python；环境默认只有标准库与 pytest；选区函数若依赖未纳入的模块，需补齐上下文或验证输入；上下文采用长度限制和 AST 摘要，没有实现大型仓库语义检索；模型格式约束与网络服务仍可能失败。

后续真实实验应同时保留成功与失败记录，固定模型配置，报告样本数量和错误请求数量。若修复后通过率提高，也需要结合额外请求次数、耗时和 token 成本分析，不能只报告最终成功案例。

## 八、总结

项目完成了以 VS Code 为入口的智能代码辅助工程，重点实现上下文组织、结构化输出、修改预览、独立测试和反馈修复。首版保留清晰的功能边界和失败状态，便于继续扩展多语言执行、项目依赖管理和更深入的上下文评估。
