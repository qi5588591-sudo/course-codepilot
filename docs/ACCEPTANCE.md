# 验收清单

## 准备

启动后端，检查 /health。配置真实 API，安装 VSIX。Python 验证需启动 Docker 并构建 sandbox 镜像。
验收过程记录模型名称、日期、需求、实际输出和失败原因。

## 功能

1. 生成：输入“实现 binary_search(nums,target)，升序无重复，未找到 -1”，结果可打开、保存、插入。
2. 多语言：在侧栏分别选择四种语言，生成简单函数。Java/JS/C++ 的实际编译执行在外部工具链完成。
3. 补全：在保存的 Python 文件函数体中触发 CodePilot: 请求代码补全，应在光标处展示片段，无旧内容重复。
4. 审查：选中 examples/binary_search_bug.py 的函数，检查末元素遗漏是否被指出。优化代码提供差异预览。
5. 测试：选中函数，生成 pytest；测试应覆盖末元素、单元素、空输入、未找到。
6. 文档：生成参数、返回值和调用示例，保存为 .md。
7. 错误诊断：输入真实错误日志，查看原因和完整修复代码。
8. 集成：插件命令、侧栏、编辑器右键入口都能调用后端。
9. 命名、函数建议、代码解释各运行一次并检查内容。
10. 测试反馈：缺陷函数配 examples/test_binary_search.py，验证失败；点击验证并修复，检查最多两轮、每轮结果与相同测试 SHA256。

## 失败路径

- 修改原文件后尝试应用旧结果：应拒绝，不覆盖新内容。
- 请求中取消：侧栏恢复可用，旧结果不得覆盖新的结果。
- 模型 API 返回 401/429/超时/格式无效：显示具体可理解的错误。
- 无 Docker、无镜像、无限循环：分别显示不可用或超时，不显示通过。
- 缺少测试或没有收集到测试：显示未验证。
- 未开启自动补全时正常编辑不产生自动模型请求。
- 关闭上下文选项时仍处理原选中代码，但不发送主动添加的相关文件。

工程自动测试不能替代云端模型效果验收。按 artifacts/VERIFICATION.md 区分已实测与待配置后完成的项目。
